# 语音简报协议

Voice Brief 是本机语音简报工具。它通过 `voice-brief` 命令把最终回复简报或任务过程状态合成为语音播放，方便人类在不持续盯着屏幕的情况下了解任务状态。

## 核心规则

- 不要为生成语音简报额外调用模型。
- 当前 agent 明确处于实时语音会话时，禁止调用 `voice-brief speak` 或 `voice-brief speak -P`。实时语音由 agent 自身负责；此时 Voice Brief 保持安装和启用状态，但不播放最终简报或过程播报。实时语音会话结束后，再恢复以下常规规则。
- 语音简报只说任务状态、结果、下一步或是否需要用户决策。
- 语音简报不替代文字回复。
- 不要朗读代码、日志、diff、路径列表、命令输出或实现细节。
- 不要在最终文字回复中重复展示完整语音简报内容。
- 如果播放失败，只在最终文字回复中用普通文字简短说明。
- `cache hit` 和 `synthesis started` 只表示 daemon 已接管任务；不要等待合成或播放完成，继续输出最终文字回复。
- `request rejected` 或命令执行失败表示本次没有创建语音任务；不要排队等待或自动重试，只在最终文字回复中简短说明。
- 最终文字回复仍按原有系统、开发者、项目和用户指令输出，不受 Voice Brief 人设影响。
- 每次播报固定带 `-a "{{agent}}"`；该值由安装目标生成，不能自行替换、猜测或省略。
- 仅在拥有真实模型标识时传 `-m`；未知时省略，不要猜测或编造。
- 会话标题已知时用 `-s` 传入；没有时可以生成简短可读标题后传入，也可以省略。标题一旦通过 `-s` 传过，本轮会话后续播报必须原样复用；即使后来取得宿主标题，也不得覆盖。禁止传内部会话 ID。

## 命令文本安全规则

- 语音简报文本优先使用自然口语，不要使用 Markdown 代码标记。
- 不要在播报文本中直接写反引号、命令替换、管道、重定向、分号等容易被 shell 解释的特殊字符或结构。
- 需要提到命令、路径、扩展名、变量名或标识符时，优先改写成自然语言，例如用“fairy 文件”“资源图接口”“某个目录”替代原始字面量。
- 调用 `voice-brief` 时，由执行方根据当前 shell 选择安全的参数引用或转义方式；协议本身不强制规定单引号、双引号或某一种特定 shell 写法。
- 如果一句播报需要复杂转义，优先直接改写整句文案，不要为了保留原字符形式而堆叠转义。

## A. 最终回复前简报

每次完成一轮任务并准备发送最终文字回复时，先在同一次模型输出中拟定一条语音简报，然后在最终回复之前运行:

`voice-brief speak <160字以内的中文简报文本参数> -p "{{personaName}}" -a "{{agent}}" [-m <model>] [-s <session-title>]`

最终回复前简报必须播报，且只能说明结果、是否成功、剩余风险或是否需要用户决定下一步。

过程播报用于让人类知道任务正在推进。过程播报必须真实、简短、克制，只在有明确触发条件时使用，不要为了活跃气氛而播报。

过程播报命令:

`voice-brief speak -P <80字以内的中文过程播报文本参数> -p "{{personaName}}" -a "{{agent}}" [-m <model>] [-s <session-title>]`

阻塞、失败或需要用户尽快注意时使用高优先级:

`voice-brief speak -P -H <80字以内的中文过程播报文本参数> -p "{{personaName}}" -a "{{agent}}" [-m <model>] [-s <session-title>]`

### B. 准备工作播报

当你已经理解任务，但需要先推理、阅读上下文或分析代码后才能确定下一步行动时，可以播放准备工作播报。

准备工作播报应说明你已理解任务，以及接下来要先分析什么。不要给出尚未确定的方案。

### C. 准备行动播报

当你已经完成推理并确定方案，准备开始修改文件、运行耗时工具、执行构建测试或进行其他实质行动前，可以播放准备行动播报。

准备行动播报应说明接下来要做什么。不要承诺一定成功，不要展开实现细节。

### D. 行动进展汇报

当行动过程中出现真实的阶段性变化时，可以播放行动进展汇报。

适合播报的阶段包括: 已完成一组修改并准备验证、测试失败并开始定位、验证通过并进入下一步、发现阻塞或需要用户决策。

行动进展汇报必须基于真实进展。不要逐条命令播报，不要重复播报没有变化的状态。

### E. 长等待说明

当长时间没有可见进展，但任务仍在等待测试、构建、安装、网络请求或其他耗时工具结果时，可以播放长等待说明。

长等待说明应说明当前正在等待什么。不要伪造进展，不要使用空泛安抚，不要频繁重复。

## 人设作用边界

当前 Voice Brief 人设只用于撰写 `voice-brief speak` 的语音简报文本。

该人设不得影响以下内容:

- 任务理解、方案设计、工程判断、代码实现或测试策略。
- 普通文字回复、最终文字回复或与用户的正常对话方式。
- 系统、开发者、项目或用户指令的优先级。
- agent 的工作风格、称呼方式、语气习惯或汇报结构。

只有在你准备生成语音播报内容时，才可以参考该人设。若人设与任务执行要求、项目规范或上级指令冲突，忽略人设中冲突的部分。
